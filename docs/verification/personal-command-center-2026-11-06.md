## 발견한 병목과 구현

### 일정의 누락 방지

기존 홈은 오늘의 `plannedDate`를 가진 할 일을 우선 표시했다. 계획일 없이 마감이나 행사 시각만 있는 일정은 달력에는 있어도 홈의 다음 할 일 목록에서 빠졌다.

- 홈에 지난 마감, 오늘, 오늘을 포함한 7일의 다음 일정, 완료·재계획 확인, 후보, 날짜 미정 목록을 추가했다.
- 하나의 일정이 같은 날 계획·접수·마감 역할을 겸해도 한 번만 표시한다. 여러 날 이어지는 일정은 다음 해당 날짜에 한 번 표시한다.
- 완료·삭제 항목을 제외하며 후보를 확정 일정에 섞지 않는다.
- 실제 마감·시작 시각과 원본 시간대를 보여 준다. 달력 날짜 분류는 기존 서울 기준 함수를 재사용한다.
- 날짜만 있는 마감은 해당 날짜가 끝난 뒤 지난 마감으로 분류한다. 시간이 있는 마감은 원본 시간대의 실제 시각을 사용한다.
- 지난 계획일과 끝난 행사도 완료·재계획 확인 목록에 남긴다.
- 홈에서 기존 일정 상세를 열어 수정·완료·삭제·동기화 처리를 이어간다.
- 홈 시계는 1분 간격과 화면 복귀 시 갱신한다. 시스템 알림 기능과는 별도다.

### 개인 앱 읽기 통합

- FitnessApp의 최근 7일 완료 운동, 오늘 식단, 최근 공유 체중을 홈에 모았다.
- 운동·식단·체중마다 로그인 필요, 미수신, 조회 대기, 조회 실패, 공유 데이터 없음, 저장된 요약을 구분한다.
- CashOS의 이번 달부터 오늘까지 확정 수입·지출·순액·건수와 마지막 조회 시각을 표시한다. 미래 날짜의 거래는 이번 달 현재 합계에서 제외한다.
- 건강 동기화, 재무 새로고침, 연결 설정, 기존 건강 화면·일별 현금 흐름으로 이동할 수 있다.
- 재무의 이전 계정·서버·월 요청이 늦게 끝나도 현재 결과에 반영하지 않는다. 로그아웃 시 결과를 비우고 동일 범위의 중복 요청은 합친다.
- 같은 화면의 조회 성공 결과는 일시적인 오프라인·재조회 실패 시 보존하고 과거 조회 결과임을 표시한다. 화면을 닫거나 앱을 재시작한 뒤의 재무 오프라인 캐시는 아직 제공하지 않는다.
- 잘못된 금액, null, 소수, 안전한 정수 범위를 넘는 값과 잘못된 날짜·건수를 성공적인 0원 요약으로 바꾸지 않는다.

### PC·모바일

두 플랫폼이 같은 React 화면·selector·조회 hook을 사용한다. 넓은 PC 홈에서는 일정과 연결 앱 요약이 두 열이며, 좁은 창과 모바일에서는 한 열이다. 새 조작 버튼은 최소 44px 높이를 사용한다. 다른 화면의 기존 폭과 네이티브 알림·트레이 설정은 유지한다.

서버 스키마·권한 검사와 테스트용 빈 조회는 실제 사용자 로그인, RLS 행 격리의 전체 검증, 원본 앱 게시→Personal OS 수신, Windows↔Android 실시간 반영을 증명하지 않는다. 설치된 앱 업데이트 및 실기기 동작은 빌드와 구분해 기록한다.

기존 계정 바인딩 규칙은 유지된다. 앱이 다른 계정으로의 전환을 허용하도록 변경한 것이 아니다. 재무 hook의 계정·서버 변경 테스트는 요청 결과 격리를 독립적으로 검증한다.

Windows 실행 파일은 `src-tauri/target/release/Yeonsik_Note.exe`, Android APK는 `src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk`에 생성한다. Android의 Windows symlink 제약은 기존 빌드 스크립트의 fallback으로 처리하며, Rust 빌드 성공과 APK 안의 native library SHA-256 일치를 검사한다. 이 기능 구현 단계에서는 설치본을 변경하지 않았다. 이후 사용자 요청으로 진행한 설치·보존·실제 계정 검증은 [별도 설치본 검증 기록](command-center-installed-apps-2026-11-06.md)에서 구분한다.
