## 데이터 보존과 설치

앱을 실행하기 전에 Windows의 기존 Roaming/Local 앱 폴더, 자동 실행 항목, Android의 앱 내부 데이터와 기존 APK를 비공개 로컬 디렉터리에 백업했다. 백업에는 계정 관련 데이터가 포함될 수 있으므로 Git에 넣지 않는다.

| 항목 | 확인 결과 |
| --- | --- |
| Windows Roaming 설정 | 2개 파일 SHA-256 동일 |
| Windows Local WebView 데이터 | 788개 파일 SHA-256 동일 |
| Android 앱 데이터 | 56개 파일 SHA-256 동일, 추가·누락·변경 0개 |
| Android 서명 | 설치본과 후보 인증서 SHA-256 일치 |

파일 해시 비교는 업데이트 직후, 앱 재실행 전에 수행했다. 앱 실행 후 동기화·캐시 갱신으로 파일이 정상 변경되는 것까지 해시 불변이라고 주장하지 않는다.

Windows는 기존 자동 실행 항목이 존재하지 않는 이전 저장소 경로를 가리키고 있었다. 실행 파일을 `%LOCALAPPDATA%/Programs/Yeonsik Note/Yeonsik_Note.exe`에 배치하고 시작 메뉴 바로 가기를 만들었다. 기존 자동 실행 활성 의도를 유지해 현재 앱이 관리하는 항목으로 옮기고 중복된 이전 항목은 제거했다. 공백이 있는 실행 경로를 따옴표로 감쌌으며, 앱 설정에 “Windows 시작 시 자동 실행됩니다.”가 표시되는 것을 확인했다. 실제 Windows 재부팅은 수행하지 않았다.

## Windows 실제 계정 수신

저장된 실제 계정 세션이 유지됐고 앱에서 로그인됨·동기화됨 상태를 확인했다. 관리자 SQL 조회만으로 수신 성공을 판정하지 않고 설치된 앱의 진단과 실제 화면을 서버 결과와 비교했다.

| 데이터 | 설치된 앱의 결과 | 서버 대조 |
| --- | --- | --- |
| Fitness 운동 요약 | `fitness_summary_projections_v2` 439개 row, connected | 같은 사용자의 439개 row 일치 |
| Fitness 식단 요약 | `fitness_nutrition_summary_v1` 32개 row, connected | 해당 사용자 claim을 적용한 읽기 전용 트랜잭션에서 32개 row 일치, rollback |
| Fitness 체중 | 42개 row, 삭제되지 않은 row 41개, connected | 같은 사용자의 전체 42개 row 일치 |
| CashOS 현재 월 | 11월 확정 내역 없음 | 마지막 요약 날짜가 10월이므로 정상 빈 결과 |
| CashOS 기존 내역 | 10월 달력 5일에 지출 표시, 10월 14일 선택 시 2건의 금액 표시 | 같은 계정의 10월 5일·6건 집계 및 선택일 수입·지출·순액 일치 |

이 검사는 기존에 게시된 FitnessApp·CashOS 데이터를 실제 Personal OS 계정으로 읽은 증거다. 원본 건강·재무 기록을 새로 작성하거나 수정해 게시 파이프라인을 시험한 것은 아니다. 운영 원본 데이터는 변경하지 않았다.

## Android 실제 계정 수신

사용자가 앱에서 같은 계정으로 로그인한 뒤, 2026-11-07 Galaxy A25의 설치된 앱 화면과 서버의 기기 heartbeat를 직접 확인했다. 비밀번호를 수집하거나 세션을 다른 기기로 복사하지 않았다.

- 설정의 Fitness 진단: 운동 요약 439개, 식단 요약 32개, 체중 42개 중 삭제되지 않은 41개가 모두 connected로 표시됐다. Windows 및 앞서 확인한 서버 집계와 일치한다.
- CashOS: 기록 → 전체 → 2026년 10월 → 14일을 선택했다. 확정 2건의 수입·지출·순액이 Windows의 같은 날짜 및 서버 조회 결과와 일치했다.
- Windows 설정의 활성 기기 목록에서 이 PC와 Galaxy A25가 함께 활성 상태로 표시됐다.
- 모바일에만 보관된 기존 일정 5개는 계정 가져오기 안내와 함께 유지됐다. 이 검증에서 해당 기록의 소유 계정 변경이나 일괄 가져오기를 실행하지 않았다.

## 양방향 메모 동기화와 재시작

기존 사용자 메모를 수정하지 않고 Windows UI에서 만든 `[QA sync 20261106-2303]` 임시 메모 하나로 검증했다. 앱 동작은 설치된 Windows UI와 실제 A25 화면에서 수행했고, 서버 SQL은 결과 확인에만 사용했다.

| 시각 (2026-11-07, KST) | 절차 | 관찰 결과 |
| --- | --- | --- |
| 00:54 | PC에서 검증 메모 제목을 `PC live 0055`로 수정 | 서버에 Windows 기기 ID로 저장. 모바일 메모 목록과 제목 입력란에 같은 수정본 표시 |
| 00:55 | 모바일에서 제목을 `Android roundtrip 0055`로 수정 | 서버에 Android 기기 ID로 저장. PC 메모 목록과 제목 입력란에 같은 수정본 표시 |
| 00:58–01:00 | PC 프로세스와 Android 앱을 종료 후 다시 실행 | 두 앱 모두 로그인·동기화 상태와 프로젝트를 유지했고, 메모 화면에서 Android가 수정한 제목·기존 본문 유지 확인. Android cold launch `Status: ok`, `LaunchState: COLD` |

양방향 수정과 삭제 반영 과정에서 수동 동기화 버튼, 직접 DB 수정, 재로그인은 사용하지 않았다. 두 기기의 메모 수정 반영을 확인한 뒤 별도 재시작 검사를 수행했다. 최종적으로 활성 QA 메모는 남아 있지 않으며 서버에는 soft-delete 기록만 남는다.

## 관찰된 오류와 검증 한계

재개 직후 모바일에는 이전의 “Supabase Realtime 구독에 실패했습니다.” 안내가 남아 있었다. Fitness 읽기 진단은 정상 상태였고, 이후 PC의 새 메모 수정이 모바일에 자동 반영되면서 오류 안내가 사라졌다. 이어 모바일→PC 수정, 재시작, PC→모바일 삭제 반영까지 성공했다. 이번에 확인한 것은 해당 실행에서의 연결 회복이며, 최초 오류의 원인이나 모든 네트워크 장애에서의 복구를 입증한 것은 아니다. 오류를 감추는 코드 변경은 하지 않았다.

이번 검증은 기존에 게시된 FitnessApp·CashOS 요약의 실제 계정 수신과 온라인 메모 동기화다. 원본 앱에 새 건강·재무 기록을 만들어 게시하는 시험, 네트워크 차단 중 편집·충돌 복구, 다른 계정 간 격리, OS 재부팅 시험은 수행하지 않았다. 재시작 중에도 네트워크를 사용할 수 있었으므로 온라인 재시작 결과를 오프라인 내구성 검증으로 확대하지 않는다. 기존 모바일 로컬 일정의 계정 병합도 별도 작업이다.

추가 설치나 애플리케이션 코드 수정은 없었다. 재시작한 Windows 설치본의 SHA-256이 위 배포 파일과 동일함을 다시 확인했다. 문서 변경은 `validate-project-docs.mjs --config project-docs.config.json --require-tracked` 다음 `sync-project-docs-to-notion.mjs --config project-docs.config.json` 순서로 검증하며, 두 번째 명령은 render-only로 실행한다.
