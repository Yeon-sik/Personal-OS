## 1. 판정

Windows와 모바일의 탐색·편집·입력 흐름을 개선하고, 코드 리뷰에서 확인한 한글 조합 및 취소 동작을 수정했다. 달력의 고정 6단 스택은 유지했다. 자동 테스트와 프런트엔드 빌드 결과는 아래 검증 표에 기록한다. 실제 모바일 기기 사용성과 Windows IME까지 검증한 결과나 정량 디자인 85점 달성으로 해석하지 않는다.

외부 앱은 공유 DB의 인증된 읽기가 정상임을 확인했지만, 실행 중인 Windows 디버그 앱의 미설정 상태와 표시·갱신 결함이 남아 있다. **전체 연동이 문제없이 완료됐다는 판정은 할 수 없다.** 외부 앱 점검에서 발견한 항목은 이번 UI 구현으로 수정되지 않았으며 후속 작업으로 구분한다.

## 2. 구현한 UX 개선

### Windows

- Windows 식별을 화면 너비와 분리해 작은 Windows 창에도 데스크톱 입력 경험을 유지한다. 넓은 창에서는 사이드 탐색과 작업 공간을 사용한다.
- 메모 검색·목록·편집을 분리하고, 삭제 확인과 저장 상태를 제공한다. 편집 중 선택 영역이 자체 저장 응답으로 초기화되지 않도록 처리한다.
- 할 일 순서는 드래그 외에 방향키·위아래 버튼으로도 변경한다. 이동 후 포커스와 변경 안내를 유지한다.
- 빠른 입력 진입 버튼에 이름을 표시하고, 폼 검증·입력 포커스·닫기 후 포커스 복귀를 보완한다.
- 홈의 상세 활동과 설정의 고급 기능을 접고 펼칠 수 있게 하고, 프로젝트 도구 영역과 기록 화면의 정보 밀도를 조정한다.

주요 근거: [Windows 레이아웃](../../src/app/WindowsDesktopContext.tsx), [Windows 스타일](../../src/app/windows-desktop.css), [Windows 메모](../../src/features/notes/WindowsMemoPanel.tsx), [할 일 목록](../../src/features/tasks/components/ChecklistTaskList.tsx).

### 모바일

- 모바일 레이아웃을 별도 컨텍스트와 스타일 범위로 분리한다. Windows에서는 모바일 레이아웃을 적용하지 않는다.
- 하단 탐색과 이름 있는 빠른 입력 버튼, 저장·연결 상태 확인 영역을 제공한다.
- 메모는 검색 가능한 목록에서 전용 편집 화면으로 이동하고 뒤로 돌아오는 흐름을 사용한다. 삭제에는 확인 단계를 둔다.
- 할 일의 일정·오늘 계획·순서 변경을 터치 가능한 컨트롤로 제공한다.
- 빠른 입력에서 Enter는 줄바꿈을 유지하고 명시적인 저장 버튼을 제공한다. 실패하거나 창을 닫아도 초안을 유지한다.
- 안전 영역과 가상 키보드에 따른 뷰포트 변화를 처리하고, 주요 터치 영역·입력 글자 크기·대비·동작 줄이기 설정을 보완한다.
- 날짜 선택 결과와 일별 기록으로 이동하는 동선을 연결한다. 작은 화면의 달력은 최소 너비 이하에서 가로로 이동할 수 있다.

### 유지한 기능과 달력 정체성

- 메모·할 일의 생성·수정·삭제·완료·일정·순서 변경은 기존 데이터 액션을 호출한다.
- 로컬 저장 모델, 동기화 계약, 인증 로직은 이번 UI 변경으로 교체하지 않았다.
- 달력의 스택은 **체중 → 식단 → 운동 → 할 일 → 오늘 할 일 완료 → 메모**의 고정 6단 순서를 사용한다. 빈 슬롯, 색상, 건수와 완료 표시를 유지한다.
- 홈·기록·프로젝트·설정의 기존 네 가지 목적지와 빠른 입력은 Windows·모바일 양쪽에서 접근할 수 있다.

## 5. 연동 점검의 미해결 문제와 후속 우선순위

### P1. 실행 중 디버그 앱의 연결 상태

설정 화면에서 로컬 저장 전용과 Supabase 연결 미설정을 확인했다. 환경 파일의 존재나 별도 점검 세션의 인증 성공은 앱 자체의 연결 성공을 의미하지 않는다. 현재 실행 바이너리의 설정 로딩 경로와 인증 상태를 확인한 뒤, 앱 화면에서 인증 읽기를 검증해야 한다. 원인은 이번 점검으로 확정하지 않았다.

### P1. CASH 비동기 응답 경합

[useFinanceCalendar](../../src/features/finance/useFinanceCalendar.ts)는 응답 시점의 월·연결·최신 요청 여부를 검사하지 않고 캐시를 교체한다. 합성 응답으로 두 경로를 재현했다.

1. 10월 조회를 시작한 뒤 11월로 이동하고 11월 응답을 먼저 수신한다. 이후 늦은 10월 응답이 캐시를 덮어쓴다.
2. 조회 중 비활성화해 캐시를 비운다. 이전 응답이 도착하면 비활성 상태에서도 캐시가 다시 채워진다.

후속 수정은 요청 세대·연결 범위의 무효화가 필요하다. 월 이동, 로그아웃·계정 전환, 늦은 성공·실패 응답에서 현재 결과와 오류 상태가 유지되는지 회귀 검증해야 한다.

### P2. FITNESS 홈 활동 집계 누락

[홈 활동 집계](../../src/features/%68ome/activity.ts)는 기존 `mealRecords`·`weightRecords`와 운동 v2를 사용한다. 현재 외부 읽기 모델인 `fitnessNutritionSummaries`, `fitnessWeightRecords`, 명시적인 공유 운동 v1 대체 경로가 빠져 있어 날짜별 기록·달력과 홈의 건수가 다를 수 있다.

다음은 개인 기록이 아닌 합성 입력으로 재현한 비교다.

| 입력 | 날짜별 기록 | 달력 | 홈 활동 |
| --- | --- | --- | --- |
| 완료 운동 v2 1건 | 1건 | 표시 | 1건 |
| 공유 운동 v1 1건 | 1건 | 표시 | 0건 |
| 식단 요약 3끼 | 3건 | 표시 | 0건 |
| FITNESS 체중 1건 | 1건 | 표시 | 0건 |

후속 수정은 [날짜별 기록 집계](../../src/features/records/recordAggregation.ts)와 외부 데이터의 노출·중복 제거 규칙을 맞춰야 한다. 전체 이력과 최근 26주 집계는 기간이 다르므로 단순 건수 비교로 누락을 판단하지 않는다. 달력 스택 구조를 변경할 필요는 없다.

### P2. FITNESS 식단의 유휴 상태 갱신 경로

식단 요약은 전체 pull에서 조회하지만 [실시간 구독](../../src/lib/sync/supabase/realtime.ts)에 식단 요약을 갱신하는 경로가 없다. 기기 활성 상태 갱신은 식단 재조회가 아니다. 따라서 PersonalOS가 유휴 상태일 때 Fitness의 식단 변경을 즉시 반영한다고 보장할 수 없다.

후속 수정에서는 상세 식단을 복제하지 않는 읽기 전용 재조회와 요약 전체 교체가 필요하다. 식단이 삭제돼 요약에서 사라진 날짜도 제거되는지 확인해야 한다.

### 현재 기능 범위

CASH는 기록 달력·금융 카드에 일별 확정 요약을 제공한다. 홈의 활동 유형에는 금융 항목이 없어 CASH 건수가 홈 활동에 포함되지 않는다. 이는 현재 집계 범위이며 CASH API 실패와 구분한다. OCR·PriceTrace 개별 이벤트를 홈 활동으로 직접 가져오는 전용 경로는 확인하지 못했다.
